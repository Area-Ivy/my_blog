在本地开发时，我们常常会看到这样一个现象：
 **HTML 页面可以直接读取电脑上的本地图片**，例如：

```html
<img src="C:/Users/you/Pictures/test.png">
```

但当项目部署到服务器后，如果你把图片路径换成服务器的本地路径：

```
/home/admin/uploads/a.png
```

前端就完全无法访问了。这让很多开发者产生一个疑惑：

> **既然前端都已经部署到服务器了，为什么还不能访问服务器本地路径？**

本文将彻底解释这个问题，并顺带讲清楚 Nginx 静态资源服务的本质。

------

## 一、核心误区：前端代码“部署在服务器”不等于“运行在服务器”

理解整个问题最关键的一点是：

> **前端代码（HTML/CSS/JS）虽然存放在服务器，但实际运行是在用户的浏览器里。**

当用户访问你的站点时：

1. 浏览器向服务器请求 `index.html`
2. 服务器把文件传给浏览器
3. **浏览器在用户电脑上执行 JS 和渲染页面**
4. 因此所有路径都基于用户电脑环境，而不是服务器

这意味着：

```
/home/admin/uploads/a.png
```

在浏览器看来是：

- 某个 Linux 电脑的本地路径
- 而用户电脑根本不是 Linux
- 浏览器也没有权限访问服务器文件系统

所以它必然无法显示。

------

## 二、为什么用户本地路径可以被访问？

当你访问：

```html
<img src="C:/Users/me/Pictures/me.png">
```

这个路径指的是 **用户自己电脑的本地文件**。
 浏览器天然运行在用户电脑上，因此可以读取（尽管也有沙箱限制）。

但这和访问服务器上的 `/home/admin/xxx` 完全不是一件事。

本地路径 ≠ 远程服务器路径
 用户电脑 ≠ 服务器电脑

------

## 三、为什么浏览器永远不能访问服务器本地路径？

浏览器只能访问以下资源：

- `http://` 或 `https://` URL
- `blob://`
- `data:` base64 数据
- 用户电脑的部分本地文件（有限制）

浏览器 **无法、也不可能** 访问：

- `/home/admin/uploads/a.png`
- `/root/secret.txt`
- `C:\Windows\xxx.dll`

因为：

1. **HTTP 协议无法直接访问服务器文件系统**
2. **安全性禁止**
3. **路径本来就是服务器操作系统专属的，不属于网络资源**

因此，要让浏览器访问服务器上的文件，必须给它一个 URL。

------

## 四、Nginx 静态资源服务就是做这件事

Nginx 的工作非常简单：

> **把服务器文件系统中的真实文件路径，映射成浏览器可访问的 URL。**

例如：

```nginx
location /static/ {
    alias /home/admin/uploads/;
}
```

浏览器请求：

```
https://yourdomain.com/static/a.png
```

Nginx 才会去文件系统找：

```
/home/admin/uploads/a.png
```

两者之间的关系是：
 **URL → Nginx → 服务器硬盘路径**

这就是静态资源服务的本质。

------

## 五、数据库为何不能保存服务器本地路径？

如果数据库保存：

```
/home/admin/uploads/a.png
```

那么前端拿到后会写成：

```html
<img src="/home/admin/uploads/a.png">
```

浏览器不会去服务器读文件，而是当作用户电脑路径看待，所以加载失败。

正确方式是：

数据库 → 存储 URL（相对路径或完整 URL）

例如：

```
/static/a.png
```

浏览器就能访问：

```
https://yourdomain.com/static/a.png
```

------

## 六、可视化理解：为什么不能直接用服务器路径？

```
┌──────────────────────────┐
│      用户浏览器（运行前端） │
├──────────────────────────┤
│ 试图访问 /home/admin/a.png → ❌ 浏览器只认 URL，不认服务器文件路径
└──────────────────────────┘

┌──────────────────────────┐
│    服务器（存储前端与图片）   │
├──────────────────────────┤
│ /home/admin/uploads/a.png  ← 真实文件路径
└──────────────────────────┘

必须这样访问：
浏览器 → https://domain.com/static/a.png → Nginx → /home/admin/uploads/a.png
```

这就是为什么**必须使用 Nginx 静态资源服务**的原因。

------

## 七、总结：一句话搞懂全部

> **虽然前端代码部署在服务器，但实际运行在用户浏览器中；浏览器无法直接访问服务器文件系统，因此必须通过 URL（Nginx 静态资源服务）来提供图片等静态资源。**
